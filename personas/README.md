# 微信人设与表情

下载来源和固定提交记录保存在 `catalog.json`。`sources/` 纳入已解压的 Word、提取的 UTF-8 纯文本以及两套表情包。原始 ZIP 仅保留在本机，不纳入 Git。Word 只提取文字，不执行宏或其他内容。

默认启用大肥鱼。人设按微信会话保存，重启后保留；新会话使用 `bridge-config.json` 的 `default_persona`。角色用于聊天语气，工作请求继续完整执行，命令仍单独放代码块。

切换大肥鱼：

```text
/persona 大肥鱼
```

切换爱弥斯（也支持“小爱”）：

```text
/persona 爱弥斯
```

恢复默认助手：

```text
/persona off
```

查看当前人设、表情数量和切换方法：

```text
/persona
```

发送当前人设的开心表情：

```text
/meme happy
```

`/meme` 默认使用 happy；无效分类会列出可用分类。日常闲聊由 Bot 主动按语境配表情，无需手动索要；模型遗漏配图标记时，简短问候、玩笑、夸奖、情绪、晚安等互动也会自动配图，补图至少间隔一轮，正式工作和严肃内容不自动补图。

静态图使用 WeiLink 图片消息发送。`bridge-config.json` 的 `animated_meme_mode` 已设置为 `file`：检测到多帧 GIF/WebP/PNG 时发送原始文件附件，完整保留字节、帧和动画时间，不重新编码。这样微信显示文件卡片，可点开或保存原始动图，不保证聊天气泡内自动循环播放。格式按文件内容识别，避免原包中扩展名为 `.jpg` 的 GIF 被错误命名。若将配置改为 `image`，则恢复全部走图片消息；缺省也维持旧图片方式。

原始下载包混有其他角色、猫狗和通用 emoji。`approved-assets.json` 是逐张视觉检查后的发送名单：大肥鱼 25 张去重原图，爱弥斯 41 张去重原图，同图可能在多个情绪分类中复用。自动配图、模型选择和手动 `/meme` 均只使用当前人设审核后的图片，原始混合素材保留但不会发送。`review/` 保存分类缩略图及内容摘要，便于核对来源。

原始大肥鱼提示词里的游戏偏好占位符保持原文；适配规则要求回复不输出占位符，也不替主人补偏好。两个人设均保留原提示词，再附加微信桥接适配规则。

图片和文字均走持久化发送队列。发生结果不明确的网络错误时不自动重发，避免重复消息；明确的会话过期或额度错误则等待主人新消息刷新。

修改前的桥接代码在本机 `backup-before-personas/` 保留，未纳入 Git；仓库中的后续修改使用 Git 历史追溯。
